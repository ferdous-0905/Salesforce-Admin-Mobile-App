# Salesforce Admin Quiz 2026

Standalone Android/iOS study app for MD Ferdous AKhter. React Native + Expo SDK 55, bundled 246-question bank, SQLite local progress, free explanations, source images, voice reading/answering and JSON backup transfer. No hosted quiz backend.

## Run

Use Node 22 LTS or newer and install dependencies with `npm install`.

- `npm run typecheck`
- `npm test`
- `npm run android:usb` — on this Mac, selects JDK 17 and the installed Android SDK, then builds/runs on a selected USB device.
- `npm run android` — requires Android Studio, Android SDK, Java and a device/emulator.
- `npm run ios` — requires macOS, full Xcode, CocoaPods and a simulator/device.
- `npm start` — starts Metro for an installed development build.

Speech recognition uses a native module: use a development build, not Expo Go. Microphone/speech permissions are requested only when answering by voice. Installed voices determine offline reading availability; recognition may use the device provider's online services.

## Builds

`npx eas-cli build --profile preview --platform android` creates a test APK after Expo account/project setup. `npx eas-cli build --profile production --platform all` creates store builds once signing and developer accounts are configured. These commands are instructions; no remote build or submission has been performed.

The configured `com.mdferdousakhter.salesforceadminquiz2026` application identifiers are provisional until registered. Keep them stable after publishing. Store legal publisher display names follow enrolled identities.

## Project structure

- `App.tsx`: native onboarding, dashboard, quiz, feedback/resources, progress and settings.
- `src/domain`: reused quiz rules and backup validation.
- `src/storage`: SQLite persistence, no network service.
- `src/hooks/useVoice.ts`: native speech and interruption cleanup.
- `assets/data`: source questions and resource mapping catalogs.
- `assets/learning`: bundled source screenshots with original provenance in the catalog.
- `tests`: grading, scoring, failed review, spoken answers and backup validation.
- `docs/DECISIONS.md`: confirmed product choices.

## Release checklist

- Test clean install, airplane-mode practice, app restart, OS interruption and app upgrades on real Android/iOS devices.
- Verify microphone denial, unsupported recognition, stop buttons, voice selection and headphones/silent mode.
- Verify 320/390px phones, tablets, large text and screen readers.
- Verify export/import and corrupt-backup rejection without losing existing progress.
- Review question accuracy, resource licenses, third-party branding and final store name before release.
- Prepare final icon/splash, screenshots, support contact, hosted public privacy-policy URL and store data disclosures reflecting actual speech providers.
- Enroll developer accounts, configure signing and identifiers, then run Play internal testing/TestFlight.
- Verify current store requirements and submit only after release checks pass.

This is an independent study app, not endorsed by Salesforce. Explanations are bundled editorial material, not generated by a live AI service. The explanation screen includes Study notes, References, Screenshots and Videos tabs. Screenshots support an enlarged offline view; videos load an embedded YouTube player on request, with in-app retry and error messages. The source catalog maps screenshots to 17 questions and videos to 22 questions; other questions show an explicit empty state.

## Developer workflow

Read `AGENTS.md`, `ARCHITECTURE.md` and `aidlc-docs/README.md`. Run `npm run check` for lifecycle structure, strict TypeScript and regression tests. The four main screen hosts remain mounted so tab round trips retain scroll, quiz state and Settings drafts. Native icons, gradients and the launcher icon require rebuilding the app; JavaScript changes use Metro. Motion follows the operating system Reduce Motion setting.

## Accounts and media discovery

The persistent Library tab lists exact question-specific screenshot/video mappings with search and filters. Practice also shows media counts before answering. Screenshots, enlarged images, video playback and online references stay in the app. YouTube needs internet. Google sign-in is integrated but disabled until real public OAuth client IDs are supplied; follow [Google setup](docs/GOOGLE-SIGN-IN.md). Existing local progress is preserved when linking.
